# Разведка площадок (2026-07-11)

Технические факты, добытые вручную. НЕ переразведывать без необходимости —
сначала проверить, что здесь написано.

## mashina.kg — ОСНОВНОЙ источник (SSR, парсится curl/httpx)

- Все страницы SSR (Next.js), отдаются httpx с браузерным User-Agent.
  Без UA — 403.
- **⚠️ 2026-09: сайт сменил вёрстку, это сломало ВЕСЬ парсинг молча**
  (search()/models_for_make()/generations возвращали 0 без единой ошибки —
  если однажды снова всё резко перестанет находиться, первым делом проверять
  ЭТО, а не credentials/blocking):
  - URL `/search/passenger` → 301 на `/catalog/passenger`. Код уже ходит
    сразу на `/catalog/passenger` (без лишнего редиректа на каждый запрос).
  - Карточка объявления: `<a class="ad-card-item">` → `<article class="...
    ad-card-item">`, сама ссылка теперь ВНУТРИ как `<a class="block"
    href="/details/...">` (обычно дублируется 2 раза). Селектор:
    `soup.select("article.ad-card-item")`, затем `card.find("a", href=True)`.
  - Город переехал из подзаголовка `<p>` в отдельный
    `<span class="...truncate">г. Бишкек</span>` вне `<p>`. Последний токен
    подзаголовка (раньше был город) — теперь тип кузова. См. `_card_city()`
    в parsers/mashina.py (ищет span с текстом `^г\.\s`).
  - Разбор HTML (`html.parser`) сам по себе не виноват — дело было чисто в
    сместившихся селекторах; lxml НЕ требовался несмотря на первое подозрение.
- **Слаги марки/модели в URL — НЕ то же самое, что значение `make=`/`model=`
  в query-параметрах.** Query-параметры принимают ТОЧНОЕ отображаемое имя
  из каталога как есть (`make=ВАЗ (Lada)` работает). А вот URL-слаг в
  `/details/<slug>-<hex>` — это транслит + вырезанная пунктуация, БЕЗ замены
  скобок/точек на дефис: `"ВАЗ (Lada)"` → слаг `vaz-lada`, не `vaz-(lada)`.
  См. `_url_slug()` в parsers/mashina.py — используется при разборе слага
  URL для восстановления марки/модели (`_model_from_card`,
  `resolve_brand_model_from_card`). Марки бывают ПОЛНОСТЬЮ кириллическими
  (УАЗ, ГАЗ, ВАЗ) — сопоставление ввода с каталогом обязательно через
  `mashina.translit()` (matching/catalog.py `resolve_make`), иначе
  латинский ввод "uaz"/"gaz" их не найдёт вообще.
- **Полное сканирование без фильтра по марке** (parsers/mashina.py
  `resolve_brand_model_from_card` + `sort_makes_by_slug_length`):
  карточка сама не знает свою марку/модель, когда `search(brand=None)`.
  Перебираем ПОЛНЫЙ каталог марок (~1873, кэш в CatalogMake) от самых
  длинных URL-слагов к коротким (иначе короткая марка типа "ГАЗ" ложно
  "съедает" длинную "ГАЗ-САЗ"), ищем префикс слага. ~3 сек CPU на страницу
  из 21 карточки — приемлемо, весь полный скан всё равно доминирован
  сетевым I/O (see matching/full_scan.py).
- **Поиск**: `https://mashina.kg/catalog/passenger?<params>` (было
  `/search/passenger`, теперь редиректит — см. выше)
  - `make=Toyota&model=Camry` — слаги РЕГИСТРОЗАВИСИМЫ и для марки, и для
    модели (`make=toyota` → 0, `model=l7` → 0, надо `LiXiang`, `L7`).
    Точные слаги марок (1879 шт.) вшиты в RSC-payload страницы поиска как
    опции с `attribute_id:16` — извлекаются fetch_makes() (резка по `},{`,
    т.к. вложенный объект meta ломает простые regex). Моделей в payload НЕТ —
    подбираем регистр перебором вариантов (resolve_model).
  - `price__gte=10000&price__lte=30000&currency=USD` — цена (Django-стиль `__gte/__lte`)
  - `year__gte=2018&year__lte=2023` — год
  - `page=2` — пагинация, ~21 карточка на страницу
  - **Любой неизвестный параметр → 0 результатов** (сервер строг)
  - Прочие имена параметров: `mileage__gte/__lte`, `engine_volume__gte/__lte`,
    `horse_power__gte/__lte`; слаги фильтров: `generations`, `car-body`, `color`,
    `transmission`, `drive`, `condition`
  - Фильтр `generations=` требует внутренние ID из закрытого API — НЕ используем,
    поколение берём из заголовка карточки
- **Карточка в выдаче**: `<a class="... ad-card-item" href="/details/<slug>-<hex-id>">`,
  заголовок в `<h3>`: `Toyota Camry VIII (XV70) Japan Market 2.5hyb CVT` —
  **поколение всегда в заголовке** (римская цифра + код в скобках).
  Подзаголовок `<p>`: `2019 ‧ 58000 km ‧ 2.5 ‧ автомат ‧ Слева ‧ седан ‧ Бишкек`.
  Цена в карточке в сомах и/или $.
- **Страница деталей**: `https://mashina.kg/details/<slug>` — SSR, 200.
  `<h1>` = заголовок с поколением. Есть «Страна учета», «Описание от продавца»,
  характеристики. external_id = hex в конце URL.
- **API api.mashina.kg**: за Cloudflare. С заголовками Origin+Referer+Accept
  отвечает чистым JSON 404, но `/api/catalog/*` (brands, filters) блокируется
  nginx 403 + CF JSD challenge. Не тратить время — SSR-страниц достаточно.
- **Справочник поколений**: НЕ качается напрямую. Стратегия V1 —
  самонаполнение: поиск make+model без фильтров, из заголовков карточек
  извлекаются поколения (regex `([IVXLC]+)\s*\(([^)]+)\)`),
  годы агрегируются min/max по карточкам. Обновляется при каждом парсинге.
  Форматы поколений в заголовках (parse_generation в parsers/mashina.py):
  1. `VIII (XV70)` — римская + код в скобках → код XV70
  2. `VIII (XV70) Рестайлинг` → код XV70-R (рестайлинг = отдельное поколение,
     как в каталоге самого сайта)
  3. `III` / `III Рестайлинг` без кода (Honda CR-V, Kia K5) → код III / III-R;
     распознаётся ТОЛЬКО если известны brand+model (срезается префикс
     заголовка, иначе "V" в "CR-V" ловится как римская цифра)
  4. Ничего из этого (LiXiang) → суррогаты `base`/`restyling`.
     Если у модели появились настоящие коды — суррогаты удаляются из БД.
- **Модели**: слаги URL транслитерированы, а отображаемое имя может быть
  кириллицей (`mercedes-benz-e-klass` ↔ «E-Класс»). _model_from_card
  сопоставляет токены заголовка со слагом через translit(); автозаполнение
  (catalog.suggest) тоже через translit — ввод "e-klass" находит «E-Класс».
  URL-параметр модели должен быть ТОЧНЫМ отображаемым именем
  (`model=E-Класс`, не `e-klass`).
- Сайт иногда отдаёт транзиентный 503 — в _fetch есть один ретрай через 5с.

## lalafo.kg — открытый JSON API (РЕАЛИЗОВАН, parsers/lalafo.py)

- `GET https://lalafo.kg/api/search/v3/feed/search`
- Обязательные заголовки: `device: pc`, `language: ru_RU`, `Country-Id: 12`,
  браузерный User-Agent. Без них — 417 с указанием недостающего заголовка.
- **category_id=1502 — «Легковые автомобили с пробегом»** (~15k объявлений).
  2044/2045 — НЕ авто (запчасти/квартиры).
- Параметры: `q=<марка модель>` (полнотекстовый, шумный — фильтровать
  заголовок по вхождению марки/модели), `price[from]`/`price[to]`+
  `currency=USD`, `per-page`, `page`, `expand=url`.
- Заголовок структурный: "Toyota Camry: 2018 г., 2.5 л, Автомат, Бензин,
  Седан" — год из него. Цена бывает в KGS → нормализуем по курсу
  config.KGS_PER_USD. `_meta.totalCount` часто фейковый (10000).
- **Сортировка (проверено 2026-10-01).** По умолчанию выдача «по
  релевантности» (`feed: ppv-category` / `search-vec-v5`): порядок плавает
  между страницами (в диапазоне 30k$+ из 2907 позиций уникальных 2309), а
  без фильтров она охватывает лишь ~18 тыс. из ~51 тыс. объявлений с ценой.
  `sort_by=newest` (`feed: category` / `search-new-v5`) — стабильный порядок
  и точный `totalCount`, но не больше **10 000** на запрос. Поэтому все
  запросы бота идут с `sort_by=newest`, а полный скан (`lalafo.scan_all`)
  режет рынок на ценовые диапазоны < 9000 объявлений (9 диапазонов, ~1300
  страниц, ~30 мин). На каждой странице +4 рекламных (повторяются).
  `per-page` > 40 работает странно (perPage 50, items 104) — не используем.
- Марка = категория объявления (лист под 1502, `/api/proxy/catalog/v3/categories/tree`),
  модель = параметр 49 в `tracking_info.params`, названия моделей —
  `/api/catalog/v3/params/filter?category_id=<марка>`.
- Поколения на lalafo НЕТ → generation_code=None, matcher фильтрует
  по году через generation_dictionary.
- Страна учета на lalafo недоступна → в фильтре учета такие объявления
  показываются с пометкой «не указана».

## unaa.kg — ИСКЛЮЧЁН ПОЛНОСТЬЮ (2026-07-14)

- unaa.kg на вебе — заглушка «Веб-сайт в разработке», весь функционал
  только через мобильное приложение. Ни парсинг, ни постинг через
  браузер невозможны. Убран из SITES/парсеров/постинга. НЕ возвращаться,
  пока не появится веб-версия (или пока не делать reverse моб. API).
